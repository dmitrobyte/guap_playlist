# Как разрабатывать и одновременно смотреть приложение

Это руководство рассчитано на работу в Windows и предполагает, что вы знакомы с основами, но не занимаетесь программированием каждый день.

## Что установить

1. **Python 3.11 или новее** — если он ещё не установлен. При установке Python включите пункт **Add python.exe to PATH**.
2. **Visual Studio Code** — редактор, в котором удобно смотреть и менять файлы проекта.
3. В VS Code установите расширение **Python** от Microsoft.

Откройте в VS Code именно папку проекта `D:\guap_playlist` через **File → Open Folder**. Откройте встроенный терминал через **Terminal → New Terminal**. Команды ниже вводятся в терминал; пути к файлам можно открывать через панель слева.

## Первый запуск

Если зависимости ещё не установлены, дважды щёлкните `install.bat` в Проводнике и дождитесь сообщения об окончании. Это нужно сделать один раз, а после изменения `requirements.txt` — повторить.

Затем:

1. Дважды щёлкните `start_server.bat`. Появится окно сервера с журналом работы. Не закрывайте его, пока используете приложение.
2. Дважды щёлкните `start_client.bat`. Откроется окно приложения. Для разработки держите его рядом с VS Code.
3. Зарегистрируйте пользователя и создайте сообщество либо заполните сервер демонстрационными данными по разделу «Демо-данные» в `README.md`.

Сервер и клиент — отдельные программы. Сервер хранит данные и обрабатывает действия, клиент показывает интерфейс. Если закрыть сервер, клиент перестанет получать данные.

## Как смотреть результат изменения

Измените файл и сохраните его в VS Code (`Ctrl+S`). Для изменений интерфейса закройте клиент и снова запустите `start_client.bat`. Для изменений серверной логики остановите сервер сочетанием `Ctrl+C` в окне сервера и снова запустите `start_server.bat`; затем обновите окно клиента или перезапустите его.

Автоматической «горячей перезагрузки» в проекте пока нет: сохранение файла само по себе не обновляет уже запущенное приложение. Окно сервера оставляйте открытым, чтобы видеть сообщения и ошибки. Если клиент запущен через `pythonw.exe`, у него нет консольного окна; для диагностики проще временно запустить его из встроенного терминала командой:

```powershell
.venv\Scripts\python.exe run_client.py
```

## Где искать нужную часть

| Что хотите понять или изменить | Файл |
|---|---|
| Вход и регистрация | `client/login.py` |
| Главное окно, список сообществ и треков | `client/main_window.py` |
| Добавление музыки, история и модерация | `client/dialogs.py` |
| Цвета, шрифты и оформление | `client/theme.py`, `client/widgets.py` |
| Воспроизведение | `client/player.py` |
| Связь клиента с сервером | `client/api.py` |
| Серверные запросы, проверки прав и бизнес-правила | `server/main.py` |
| Таблицы и соединение с SQLite | `server/db.py` |
| Рейтинг и переход между неделями | `server/ranking.py` |

Обычно изменение внешнего вида находится в `client/`. Изменение правил (например, кто может голосовать) требует проверки серверной части `server/`: интерфейс не должен быть единственной защитой. Изменения базы требуют особой осторожности, потому что данные хранятся в `server/data/` и переживают перезапуск.

## Безопасный рабочий ритм

1. Перед началом посмотрите текущую ветку и изменения во вкладке **Source Control** VS Code. Не переключайте ветку и не нажимайте **Commit** или **Sync/Push**, пока не понимаете, что именно будет отправлено.
2. Попросите описать конкретную небольшую задачу простыми словами: какой файл затронут и что должно измениться в окне.
3. Посмотрите результат в запущенном приложении.
4. Если менялось поведение, запустите `run_tests.bat` и убедитесь, что проверки завершились успешно.
5. Перед следующей задачей просмотрите список изменённых файлов и краткое описание каждой правки.

Не удаляйте `server/data/`, если хотите сохранить созданные аккаунты, сообщества и загруженную музыку. Для безопасных экспериментов используйте отдельную папку данных, например запуск сервера командой:

```powershell
.venv\Scripts\python.exe run_server.py --data-dir demo_data
```

Папка `demo_data` будет отдельным хранилищем и не затронет обычные данные сервера.

## Как просить о помощи с изменением

Удобный формат задачи:

> Хочу, чтобы [что именно изменилось]. Сейчас приложение [что происходит]. Измени только нужные части, объясни простыми словами, как проверить результат, и не делай commit или push.

Можно приложить скриншот окна и указать, на каком экране или после какого действия возникает проблема.
