# Совместный плейлист группы или факультета

Настольное приложение для Windows: участники сообщества вместе добавляют музыку,
голосуют за треки, и сервер сам выстраивает порядок воспроизведения. Каждую неделю
голосование начинается заново, а итоги прошлых недель сохраняются в истории.

**Стек:** Python · PySide6 (интерфейс и проигрыватель) · FastAPI + Uvicorn (сервер) ·
SQLite (база) · HTTPX (запросы клиента к серверу).

---

## 1. Как это устроено (простыми словами)

```
 Клиент (окно на ПК)  ──HTTP/JSON──►  Сервер (FastAPI)  ──►  SQLite + папка с файлами
 Клиент (другой ПК)   ──HTTP/JSON──►        ▲
```

* **Сервер** запускается **на одном** компьютере. Только он хранит базу и файлы,
  проверяет права, считает голоса и рейтинг.
* **Клиенты** запускаются на любом количестве компьютеров и только «спрашивают»
  сервер. Поэтому все видят один и тот же плейлист.
* Клиент **никогда** не открывает базу напрямую — только через API.

## 3. Установка на Windows (один раз на каждом компьютере)

1. Установите **Python 3.11 или новее** с <https://www.python.org/downloads/>.
   В первом окне установщика **обязательно поставьте галочку «Add python.exe to PATH»**.
2. Распакуйте папку проекта, например в `C:\shared_playlist`.
3. Дважды щёлкните **`install.bat`**. Он создаст папку `.venv` (отдельное окружение,
   чтобы не мешать другим программам) и установит библиотеки. Это займёт 1–3 минуты.

## 4. Запуск

### Сервер (на одном компьютере)
Дважды щёлкните **`start_server.bat`**. Откроется чёрное окно с адресами:

```
 На этом компьютере:   http://127.0.0.1:8000
 Для других в сети:    http://192.168.1.25:8000
```

Не закрывайте это окно — пока оно открыто, сервер работает.
Если Windows спросит про брандмауэр — нажмите **«Разрешить доступ»** (для частной сети),
иначе другие компьютеры не смогут подключиться.

### Клиент (на каждом компьютере, включая компьютер с сервером)
Дважды щёлкните **`start_client.bat`**. В поле «Адрес сервера» укажите:
* на компьютере с сервером — `http://127.0.0.1:8000`;
* на других — адрес «Для других в сети» из окна сервера.

После первого входа клиент запоминает сессию: при следующем запуске войдёт сам.

### Демо-данные (по желанию)
При запущенном сервере выполните в папке проекта:
```
.venv\Scripts\python tools\seed_demo.py
```
Появятся пользователи `anna`, `boris`, `vera` (пароль `demo123`) и сообщество
«Группа ИВТ-21» с треками и голосами.

## 5. Автотесты

Дважды щёлкните **`run_tests.bat`**. 13 тестов проверяют критерии приёмки 1–20 из ТЗ:
регистрацию, повторный логин, приглашения, три способа добавления, голоса и отзыв,
сортировку, историю, модерацию, ротацию недели, сохранность данных после перезапуска,
скорость на 100 треках. Все должны быть зелёными (`passed`).

### Проверка интерфейса
При запущенном сервере на **чистой** папке данных:
```
start_server.bat --port 8766 --data-dir ui_test_data
.venv\Scripts\python tests\ui_smoke.py http://127.0.0.1:8766 screenshots
```
Скрипт сам регистрируется, создаёт сообщество, голосует кликом, запускает плеер,
открывает все диалоги и сохраняет 14 скриншотов в папку `screenshots`.

## 6. Как проверить недельную ротацию, не дожидаясь понедельника

Запустите сервер **на отдельной папке данных** с подменённой датой (чтобы не путать
основную базу):

```
start_server.bat --data-dir demo_data --fake-now 2026-10-14T12:00
```
Проголосуйте за что-нибудь. Закройте сервер (Ctrl+C) и запустите снова с датой
следующей недели:
```
start_server.bat --data-dir demo_data --fake-now 2026-10-19T00:05
```
Откройте сообщество: голоса обнулились, а в «Истории» в списке недель появилась
прошлая неделя со статусом «завершена» и её итоговым рейтингом.

## 7. Сценарий демонстрации на защите (≈ 5 минут)

1. Запустить сервер, показать адрес. Запустить два клиента (два ПК или два окна).
2. **Анна** регистрируется → «+ Создать сообщество» → код приглашения скопирован автоматически
   (бейдж «Код: …» в шапке тоже копирует его по клику).
3. **Борис** регистрируется → «Вступить по коду» → видит то же сообщество.
4. Анна: «+ Добавить музыку» → **Библиотека** → два трека. Борис: **Файл** (перетащить MP3/WAV)
   и **Ссылка** (https://…). Через ≤5 секунд все три вида видны у обоих.
5. Оба голосуют пилюлей [▲ N]. Показать: число голосов, стрелки ▲/▼ при смене мест,
   залитая изумрудом пилюля своего голоса. Повторное нажатие — голос отозван.
6. Кнопка ▶ в строке — трек скачивается с сервера и играет; ↗ — ссылка открывается в браузере.
   Пока играет трек, Борис голосует — играющий трек не прерывается, а «⏭ Следующая»
   берёт лучший по **новому** рейтингу.
7. «История и ротация» — итоги недель и журнал: кто и когда голосовал.
8. Анна (владелец): навести на строку → «Скрыть» → трек исчез у обоих. У Бориса кнопки нет,
   а сервер в любом случае отвечает «Недостаточно прав» (это проверяет тест).
   «Модерация»: вернуть трек, назначить Бориса модератором, сменить код.
9. Ротация недели — по разделу 6 (или показать прохождение `run_tests.bat`).
10. Закрыть и снова открыть клиент и сервер — всё на месте.

## 8. API (контракт между клиентом и сервером)

Полная интерактивная документация: `http://127.0.0.1:8000/docs` (можно жать «Try it out»).
Все запросы, кроме регистрации и входа, требуют заголовок `Authorization: Bearer <токен>`.
Ошибки всегда в одном формате: `{"error": {"code": "...", "message": "сообщение на русском"}}`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/auth/register` | регистрация → `{token, user}` |
| POST | `/auth/login` | вход → `{token, user}` |
| GET | `/auth/me` / POST `/auth/logout` | текущий пользователь / выход |
| GET / POST | `/communities` | мои сообщества / создать |
| POST | `/communities/join` | вступить по коду |
| GET | `/communities/{id}` | сообщество + текущий период |
| GET | `/communities/{id}/members` | участники |
| POST | `/communities/{id}/members/{user_id}/role` | назначить/снять модератора (владелец) |
| POST | `/communities/{id}/invite/regenerate` | новый код (старый перестаёт работать) |
| GET | `/catalog` | подготовленная библиотека |
| GET | `/communities/{id}/tracks` | треки (`?include_hidden=true` — для модераторов) |
| POST | `/communities/{id}/tracks` | добавить из каталога или ссылку |
| POST | `/communities/{id}/tracks/upload` | загрузить MP3/WAV (до 20 МБ) |
| GET | `/communities/{id}/playlist` | рейтинг текущей недели |
| POST / DELETE | `/tracks/{id}/vote` | проголосовать / отозвать голос |
| GET | `/communities/{id}/periods` | список недель |
| GET | `/communities/{id}/history?period_id=` | рейтинг недели + события голосования |
| PATCH | `/tracks/{id}/moderation` | `{"status": "hidden"}` или `"active"` |
| GET | `/tracks/{id}/file` | аудиофайл для участника |

## 9. Интерфейс

Тёмная тема в палитре Zinc / Obsidian, шрифт Segoe UI. Все цвета лежат в `client/theme.py`.
* Изумрудный акцент `#10B981` используется только для главной кнопки, полосы прогресса,
  своего голоса и топ-3 позиций.
* Иконки (▶, ⏸, ■, ⏭, ↗, звук) и обложки треков рисуются векторно через QPainter.
  Обложка — приглушённый цвет по хешу названия и инициалы исполнителя. Цвет одинаков
  на всех компьютерах.
* Строки плейлиста — карточки высотой 56 px с подсветкой при наведении. Кнопка
  «Скрыть» появляется только при наведении, чтобы не шуметь.
* Изменение места в рейтинге показывают стрелки ▲/▼ под номером.
* На Windows 10/11 шапка окна тоже становится тёмной.

## 10. Важные решения (на случай вопросов комиссии)

* **Рейтинг считает только сервер**: клиент присылает лишь «голосую»/«отзываю».
  Порядок: больше голосов → раньше добавлен → меньший id.
* **Один голос на трек за неделю** гарантирует база: уникальный ключ
  `(period_id, track_id, user_id)`. Голос и запись в историю меняются в одной транзакции.
* **История неизменна**: каждое действие — отдельная строка в `vote_events`;
  итоги недели сохраняются копией в `playlist_snapshots` (с названием на тот момент).
* **Удаление = скрытие**: история и прошлые недели не теряются.
* **Ротация без фоновой службы**: при каждом обращении сервер проверяет, не наступил ли
  понедельник (Europe/Moscow, меняется переменной `PLAYLIST_TZ`). Проверка внутри
  транзакции, поэтому снимок недели сохраняется ровно один раз.
* **Безопасность**: пароли — PBKDF2-SHA256 с уникальной солью; в базе хранится только
  хеш токена; файлы сохраняются под случайными именами; проверяется размер, расширение
  и **реальное содержимое** файла (подпись MP3/WAV); ссылки — только http/https.
* **Окно не зависает**: все сетевые операции и скачивание файлов идут в фоновых потоках.

## 11. Настройки сервера (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PLAYLIST_DATA_DIR` | `server/data` | где лежат база и загруженные файлы |
| `PLAYLIST_TZ` | `Europe/Moscow` | часовой пояс для границ недели |
| `PLAYLIST_MAX_UPLOAD_MB` | `20` | лимит размера файла |
| `PLAYLIST_TOKEN_TTL_HOURS` | `168` | срок действия входа (7 дней) |

## 12. Сборка EXE (необязательно)

`build_exe.bat` соберёт клиент в `dist\SharedPlaylist\SharedPlaylist.exe` —
его можно запускать на компьютерах без Python.

## 13. Частые проблемы

* **«Не удалось подключиться к серверу»** — сервер не запущен, неверный адрес
  или брандмауэр блокирует порт 8000. Проверьте, что компьютеры в одной сети.
* **Нет звука у загруженного WAV/MP3** — проверьте файл в обычном плеере;
  Windows 10/11 воспроизводят оба формата.
* **«Сессия истекла»** — просто войдите снова.
